# KARMA defence loop

KARMA currently uses a signed-in local account to select a bounded private view of that participant&rsquo;s advisory observations. The account identifier is excluded from the decision and evidence hash. A closed purpose-specific catalog returns an explainable proposed response, while the effective response is always `observe`.

It does not change accounts, trust, trades, escrow, payments, refunds, or payouts. It does not publish reputation or retaliate against an apparent attack source. The portable CashLoom design requires no central identity; Cambridge&rsquo;s narrower adapter uses its existing local session only for private row selection.
