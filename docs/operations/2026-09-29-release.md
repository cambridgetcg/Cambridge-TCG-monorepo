No database migration, backfill, provider acquisition, credential rotation,

## First module review: native prices

The module pass traced SKU identity, pricing calculations, source parsers, write
validation, feed projection and publication permissions. It found inconsistent
defenses, not evidence of corrupt production rows.

The writer now calls the same normalized-value validator as the reader. Native
decimal strings, currency/underlying-market pairs, source granularity and
exact/unresolved mapping fields agree across writer, reader and JSON Schema.
Cardmarket product aggregates retain unknown language/condition. Trailing line
terminators no longer pass native-price patterns. Raw numeric source values
still become strings during parsing. Permission and provenance checks remain
separate; valid syntax does not verify a physical printing or authorize use.

Malformed writes fail before opening a transaction. Existing inconsistent rows
make their bounded response page unavailable rather than emit partial invalid
data. No historical records are rewritten. See the
[contract ownership and limits](../architecture/card-data-contracts.md) and
[module map](../modules/README.md).

## Dependency disposition

Nodemailer is pinned to 9.1.0 in storefront and the shared email package. Both
direct paths and the installed storefront Auth.js chain resolve the patched
version. This addresses the maintainer's
[address-parser advisory](https://github.com/nodemailer/nodemailer/security/advisories/GHSA-2x7j-588g-ccc2).
The upgrade's default TLS verification for remote attachment/OAuth2/proxy HTTPS
fetches does not change the application's literal MIME body and SES/basic-SMTP
configuration paths. No transport credentials or production settings changed.

Auth.js currently declares a Nodemailer 7/8 peer range. The 9.1.0 peer warning
remains visible and is not suppressed; installed-chain resolution, mail/auth
fixtures, full storefront tests and the production build passed. Other apps'
optional older mail dependencies remain outside this promotion.
The focused mail/auth pass covered 147 tests plus actual in-memory MailComposer
and stream-transport MIME generation, including recipient-limit rejection;
it made no provider requests and does not establish live delivery.

The final production dependency audit is **not clean**: workspace metadata
reports eight critical, 63 high, 56 moderate and eight low findings. The
storefront-filtered paths include 15 high/critical advisories. The unchanged
Drizzle identifier, Undici proxy/WebSocket/cache, PostCSS, Nanoid and DeepmergeTS
call-path dispositions are recorded in the
[September 7 evidence](../ops-github-auth-release-2026-09-07.md#production-dependency-audit-disposition).
This release adds no callers to those vulnerable APIs; CardRush acquisition
remains hard-disabled.

The additional
[Windows-hosted Next issue](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)
does not match the Vercel Linux deployment target. Storefront retains unconditional
`images.unoptimized: true`, and no direct Sharp caller was found, keeping the
[Next AVIF optimizer issue](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)
and [Sharp libheif issue](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c)
outside that runtime image-processing path. This is a bounded applicability
assessment, not a claim that Next/Sharp are patched. Reassess before changing
hosting, image optimization, proxy acquisition or the named call paths. The
future Sharp patch threshold is 0.35.4, not the older 0.35 guidance alone.

## Production verification procedure

After pushing the qualified commit, require a ready deployment for that exact
SHA and match the `cambridgetcg.com` alias to it. Probe the new homepage, roadmap,
card-data descriptor and image/native-price schema routes, then run the canonical
`pnpm audit:deploy-verify -- --skip-wholesale` for this storefront promotion.
Its bodyless mutation probes were reviewed: absent auth/signature/origin/payload
is rejected before domain mutations. Send no account cookies or credentials.

Image eligibility may intentionally withhold incomplete legacy references; source
accuracy, rights, exact-printing crosswalks, independent gallery/PvP readers and
object/cache revocation remain separate work in the
[integration roadmap](../plans/tcg-data-platform/README.md).
